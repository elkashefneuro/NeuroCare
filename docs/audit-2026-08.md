# NeuroCare audit — August 2026

Audit of the bilingual patient-education site, plus the fixes applied in the same
change. Verified against `bun run lint`, `bun run typecheck`,
`bun run check:content`, `bun run build`, and a headless-browser pass over the
running app.

Severity is judged from the perspective of a patient reading clinical guidance:
availability and clarity of the guidance outrank everything else.

---

## Fixed in this change

### 1. Content validation could take the whole site down — critical

`src/content/conditions.ts` ran `validateConditions()` at **module scope**, and
that module is imported by every route. One of the publish rules is time-based:

```ts
const today = new Date().toISOString().slice(0, 10);
if (condition.nextReviewDate < today) {
  /* validation error */
}
```

So on the day a published guide passed its `nextReviewDate`, the import threw,
and **every request to every page** — English and Arabic, index and article —
became a 500. Nothing about that failure mode depends on a deploy: a site that
had been serving fine for a year would go dark overnight. The stroke guide's
review date is `2027-06-15`, so this was a dated fuse, not a hypothetical.

**Fix.** The strict gate moved to `src/content/validate.ts`, imported only by the
Vite build plugin and `bun run check:content`. `conditions.ts` is now a plain
data module. Schema mistakes still fail the build — which is where an editorial
error should surface — but they can no longer fail a request.

An overdue review is now _disclosed_ rather than fatal: `src/lib/review.ts`
drives a notice on the article telling the reader the guide has passed its review
date and to check time-sensitive details with their doctor. That is the clinically
appropriate response — a patient losing the page entirely is worse than a patient
reading it with a caveat.

The publish gate also now takes `now` as an argument instead of reading the
ambient clock, so the rule is deterministic and testable, and it rejects
duplicate slugs (previously two guides could claim one URL and the second would
be unreachable).

### 2. Arabic pages served as English documents — high (accessibility, SEO)

`RootShell` hard-coded `<html lang="en">` and set no `dir`. `SiteLayout` patched
`document.documentElement` in a `useEffect`, so the correction only existed after
hydration, and never at all for the 404 page.

Every Arabic page therefore shipped as `<html lang="en">` with no `dir="rtl"`.
A screen reader announced Arabic text with an English voice — for a site whose
whole purpose is reaching Arabic-speaking patients, that is the accessibility
failure that matters most.

**Fix.** `RootShell` derives the locale from the URL and renders
`<html lang="ar" dir="rtl">` server-side. Confirmed in the served HTML and across
a client-side language switch. The redundant `useEffect` was removed.

### 3. Open Graph URLs were unresolvable — medium (SEO)

`og:url` was emitted as `/en/conditions/stroke-and-tia`. Open Graph has no
relative form; social crawlers cannot resolve it. `rel="canonical"` was relative
too — legal, but weaker than an absolute canonical.

**Fix.** `src/lib/site.ts` reads `VITE_SITE_URL`. When set, canonical, `hreflang`
and `og:url` are absolute. When unset, canonical and `hreflang` stay relative and
`og:url` is **omitted** rather than emitted broken. No default domain is guessed:
a canonical tag pointing at the wrong host is worse than none.

Also added: `og:site_name`, `og:locale` and `og:locale:alternate` per page.

### 4. No sitemap, no structured data — medium (SEO)

**Fix.** A build plugin emits `/sitemap.xml` (with `xhtml:link` hreflang
alternates and per-guide `lastmod` from the review date) and appends the
`Sitemap:` directive to `robots.txt`. In-review guides are excluded — they carry
`robots: noindex`, so listing them would contradict the page's own instruction.
Both are skipped with a warning when `VITE_SITE_URL` is unset.

Published pages now carry schema.org JSON-LD: `MedicalWebPage` for guides
(author, `reviewedBy`, `lastReviewed`, `MedicalAudience`, cited guidelines) and
`CollectionPage` for each library index. In-review pages emit none — an unreviewed
draft must not advertise itself as reviewed medical content.

### 5. Zod shipped to every browser — medium (performance)

Because validation ran at import time, the whole zod runtime plus the schema was
bundled into the client. The conditions chunk was **109 KB**; it is now **56 KB**,
with zod absent from the client build entirely. This fell out of fix #1.

### 6. Mislabelled definition list — medium (accessibility)

The article metadata block paired the wrong terms:

```tsx
<dt>{content.category}</dt>          // "Vascular"
<dd>{t.readTime(...)}</dd>           // "8 min read"
```

A screen reader announced "Vascular: 8 min read". **Fix.** A real
`Reading time` / `مدة القراءة` label was added in both locales.

### 7. Filtering was silent for screen-reader users — medium (accessibility)

Typing in the search box or picking a category rewrote the results list with no
announcement and no visible count; only the empty state said anything. **Fix.**
A `role="status" aria-live="polite"` region reports the result count in both
languages, and the empty state now lives in the same region.

### 8. Search missed the guide bodies — medium (usability)

Search covered only title, summary and category. A patient searching a symptom —
"slurred speech", "تنميل" — got no results even when the guide's _Recognise_
section was about exactly that.

**Fix.** Search now indexes every section heading and block in both languages,
built once per mount rather than per keystroke, and matches all whitespace-
separated terms. Verified: "slurred speech" now finds the stroke guide.

### 9. `/favicon.ico` 404'd on every page load — low

`__root.tsx` linked a file that did not exist in `public/`. **Fix.** Added
`public/favicon.svg` in the brand palette and pointed the link at it.

### 10. CI never ran the linter — low (hygiene)

CI ran only `check:content` and `build`. `bun run lint` failed on `main` with
**39 errors** (all Prettier formatting) and nothing surfaced it. **Fix.** Lint and
a new `bun run typecheck` run in CI ahead of the content gate, and the 39 existing
errors are cleared. Lint is now clean; the 6 remaining warnings are
`react-refresh` notices from unmodified shadcn/ui boilerplate.

### 11. 404 page was English-only — low

An Arabic reader hitting a bad URL got an English page with a link to `/`. **Fix.**
The 404 reads the locale from the URL and renders in the right language,
direction and back-link, with a 44 px touch target.

## Noted, not changed

| Item                                             | Why it was left                                                                                                                                                               |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No `og:image`                                    | Social cards render bare. Needs a real designed asset and a decision on branding — an auto-generated placeholder would look worse than none.                                  |
| "Print these questions" prints the whole article | `window.print()` with only `print:hidden` helpers. A print stylesheet scoped to the _Ask_ section would match the label. Editorial call on what belongs on the printed sheet. |
| Arabic reading-time plural                       | `قراءة ${n} دقائق` is wrong for n = 1, 2 and 11+. Arabic has six plural forms; correct handling wants `Intl.PluralRules`, which is a wider i18n change than this pass.        |
| `vite preview` is broken                         | It looks for `dist/server/server.js` while the build emits a nitro bundle to `.output/`. Pre-existing; `bun run dev` and the deployed worker both work.                       |
| Vite config-loader extension warnings            | Pre-existing noise from `configLoader: 'native'` about extensionless relative imports. Silencing it means touching app-code import paths for no runtime benefit.              |
| Only one guide is published                      | Migraine and epilepsy are correctly gated as `in-review` and `noindex`. Content, not code.                                                                                    |
